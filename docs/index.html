Exercise 3

Field Expansion: Add Total Flight Hours

Use Bob to plan then implement a new business field — Total Flight Hours — from the physical file all the way to the 5250 screen.

⏱ ~30 minutesIBM i Developer mode, Library List scope
💡

Before you begin: Switch to IBM i Developer mode, set scope to Library List (QSYS), and confirm FLGHT4nn is on the library list. You stay in Developer mode for the whole exercise.

Field Spec at a Glance

LayerField NameDefinition
Database (PF)FLHRS4P 0 (packed, 4 digits, 0 decimals)
Logical / RPGFHRSRENAME(FLHRS)
Screen (DDS)SFLHRS4/0, input/output, after Mileage

3a Create a Custom Rule

1

Open Bob settings

Click the settings icon at the top right of the Bob panel.

2

Navigate to IBM i Developer mode

Click Modes on the left sidebar → select IBM i Developer.

3

Open the mode editor

Click the pencil (edit) icon in the top right.

4

Add custom instructions

Scroll to the Custom Instructions section and add the following text, then click Save:

Custom Instructions to paste 
## When a user asks to plan or implement code changes
- Make insert-only changes using apply_diff with surrounding context; do not use insert_content.
- When inserting, anchor the diff on the line ABOVE the insertion point and do not include
  trailing structural lines (DDS key "K ..." or record-format "R ..." lines) in the
  replacement - leave those lines untouched.
- When adding a fixed-form entry that mirrors an existing one (RPG I-spec, O-spec, or DDS
  field), copy the model line's EXACT column positions and change only the field name and
  value. Re-pad so numbers stay right-justified in their original columns and the data-type
  letter stays in its column. If the new field name is a different length than the model,
  adjust the padding so every downstream column is unchanged. Never eyeball the spacing.
- Preserve exact DDS column positions for field-definition entries (name, length, type).
  Keyword continuation lines like COLHDG only need to start after position 44.
- Preserve the existing OPM RPG fixed-column style.
- Do not add ALWNULL, do not use SQL ALTER TABLE, do not change the field to 5P 1.
- COLHDG belongs only in the physical file, never in the display file.
- Always show the diff and wait for my approval before saving; never compile until I say so.
✅

Exercise 4

Database Query Optimization

Review a complex SQL query written by a junior developer, validate and correct it with Bob, analyze performance bottlenecks, and apply the Index Advisor workflow.

⏱ ~15 minutesIBM i Database mode

4a Switch Mode

In the Bob chat panel, use the mode selector to switch to IBM i Database mode.

4b Review the Query

Type /review first so it highlights in the Bob chat, then paste the query below. Replace all four occurrences of FLGHT4nn with your library number before sending.

SQL Query — paste after /review 
SELECT
    f.FLIGH00001                                    AS FLIGHT_NUMBER,
    f.DEPARTURE                                     AS FROM_CITY,
    f.ARRIVAL                                       AS TO_CITY,
    f.AIRLINES                                      AS AIRLINE,
    f.DAY_O00001                                    AS DAY_OF_WEEK,
    f.DEPAR00002                                    AS DEPARTURE_TIME,
    f.ARRIV00002                                    AS ARRIVAL_TIME,
    f.MILEAGE,
    f.TICKE00001                                    AS TICKET_PRICE,
    f.SEATS00001                                    AS SEATS_AVAILABLE,
    ag.AGENT_NAME,
    COUNT(DISTINCT o.CUSTO00001)                    AS UNIQUE_CUSTOMERS,
    SUM(o.TICKE00001)                               AS TOTAL_TICKETS_SOLD,
    SUM(CASE WHEN o.CLASS = 'F' THEN o.TICKE00001 ELSE 0 END) AS FIRST_CLASS_TICKETS,
    SUM(CASE WHEN o.CLASS = 'B' THEN o.TICKE00001 ELSE 0 END) AS BUSINESS_TICKETS,
    SUM(CASE WHEN o.CLASS = 'E' THEN o.TICKE00001 ELSE 0 END) AS ECONOMY_TICKETS,
    MIN(o.DEPAR00001)                               AS EARLIEST_BOOKING_DATE,
    MAX(o.DEPAR00001)                               AS LATEST_BOOKING_DATE
FROM FLGHT4nn/FLIGHTS       f
JOIN FLGHT4nn/ORDERS        o  ON o.FLIGH00001  = f.FLIGH00001
JOIN FLGHT4nn/AGENTS        ag ON ag.AGENT_NO   = o.AGENT_NO
LEFT JOIN FLGHT4nn/CUSTOMERS c  ON c.CUSTO00001  = o.CUSTO00001
WHERE o.DEPAR00001 >= TIMESTAMP('2004-02-08-00.00.00')
  AND o.DEPAR00001 <  TIMESTAMP('2004-02-11-00.00.00')
GROUP BY
    f.FLIGH00001, f.DEPARTURE, f.ARRIVAL, f.AIRLINES,
    f.DAY_O00001, f.DEPAR00002, f.ARRIV00002,
    f.MILEAGE, f.TICKE00001, f.SEATS00001, ag.AGENT_NAME
ORDER BY
    o.DEPAR00001,
    f.FLIGH00001
FETCH FIRST 100 ROWS ONLY;
⚠️

Intentional bug to spot: o.DEPAR00001 appears in ORDER BY but not in GROUP BY — logically incorrect on strict SQL engines. Bob's /review should flag this.

Expected findings from Bob:

  • ❌ ORDER BY o.DEPAR00001 uses a non-grouped column — may cause SQL0122
  • ⚠️ The LEFT JOIN to CUSTOMERS is unused and can be removed
  • ⚠️ TICKET_PRICE is stored as VARCHAR(22) — requires validation before numeric calculations
  • ✅ The CASE-based class breakdown is a clear, set-based approach
  • ✅ FETCH FIRST 100 ROWS ONLY is a good testing safeguard

What is MCP?

The Model Context Protocol (MCP) is an open protocol that standardizes how AI applications interact with external data sources and tools — a universal adapter that allows Bob to:

  • Access Data Sources — Connect to databases, APIs, and file systems
  • Execute Tools — Run SQL queries, system commands, and custom operations
  • Maintain Context — Keep track of conversation state across interactions
ConceptDescription
MCP ServerA service that exposes tools and resources to AI agents
TransportCommunication method (HTTP for remote, Stdio for local)
ToolsExecutable operations (SQL queries, system commands)
ResourcesData sources (databases, files, APIs)
AuthenticationSecurity layer (tokens, credentials)

      JOIN CUSTOMERS c ON o.CUSTOMER_ID = c.CUSTOMER_ID

⚠️

Common mistakes Bob may need to self-correct:

System Value Auditing — use sysvalue not sysval

audit_security.yml 
- name: Audit system security values
  ibm.power_ibmi.ibmi_sysval:
    sysvalue:
      - {name: 'QSECURITY',  expect: '50'}
      - {name: 'QINACTMSGQ', expect: '*DSCJOB',  check: 'equal_as_list'}
      - {name: 'QMAXSIGN',   expect: '000003'}
      - {name: 'QALWOBJRST', expect: '*NONE',    check: 'equal_as_list'}
  register: sysval_audit
  failed_when: false

Library Permissions — use operation: display not query

audit_security.yml 
- name: Audit public authority on MYAPP_DB
  ibm.power_ibmi.ibmi_object_authority:
    object_name: 'MYAPP_DB'
    object_type: '*LIB'
    user: '*PUBLIC'
    operation: display
  register: myapp_public_auth
  failed_when: false

Setting System Values — use ibmi_cl_command not ibmi_sysval

📋

ibmi_sysval is read-only. To change a system value, use ibmi_cl_command with CHGSYSVAL in the remediation playbook.

remediate_security.yml 
- name: Set QINACTMSGQ to disconnect inactive sessions
  ibm.power_ibmi.ibmi_cl_command:
    cmd: "CHGSYSVAL SYSVAL(QINACTMSGQ) VALUE(*DSCJOB)"

Privilege Elevation — use module-level become_user

⚠️

Standard Ansible become: does NOT work on IBM i. Use become_user and become_user_password as module-level arguments instead.

remediate_security.yml 
- name: Remediate QINACTMSGQ (requires *SECADM)
  ibm.power_ibmi.ibmi_cl_command:
    cmd: "CHGSYSVAL SYSVAL(QINACTMSGQ) VALUE(*DSCJOB)"
    become_user: 'QSECOFR'
    become_user_password: '{{ qsecofr_password }}'
💡

For this lab, ITZUSER already has *ALLOBJ and *SECADM — you can omit become_user/become_user_password entirely.

Exercise 1 Security & PTF Reporting

1.1 — PTF Status Report

Bob Prompt — IBM i Database mode
"Generate a PTF status report for my IBM i system. Show me missing PTFs, their descriptions, and whether they require an IPL."

Expected: PTFs ranked by status (NOT APPLIED, APPLY PENDING, APPLIED) with IPL-required flags. Group PTF levels (e.g., SF99xxx Db2, SF99722 Java).

Refinements to try:

  • "Which PTFs are loaded but not yet applied?"
  • "Show me the current Group PTF levels for Db2 and Java."
  • "Are there any PTFs that require an IPL to take effect?"

1.2 — Security Audit Report

Bob Prompt
"Run a security audit on my IBM i. Check for user profiles with default passwords, profiles with *ALLOBJ authority, and any publicly accessible sensitive objects."

Expected: User profiles with expired/default passwords or inactive for 90+ days. Profiles holding *ALLOBJ, *SECADM, or *JOBCTL. Objects with *PUBLIC *CHANGE or *PUBLIC *ALL flagged as risks.

  • "Which user profiles have not logged in for more than 90 days?"
  • "Show me all profiles with *ALLOBJ authority that are not IBM-supplied."
  • "Are there any objects in production libraries accessible to *PUBLIC?"

1.3 — Generate a Markdown Report

Bob Prompt
"Write a concise Markdown security and PTF summary report and save it to the IFS under my home directory."

Expected: A .md file saved to /home/<your_user>/ containing PTF gap and security findings tables, ready to share with your team.

Exercise 2 CPU Troubleshooting

2.1 — Identify the Top CPU Consumers

Bob Prompt
"Show me the top 10 jobs consuming the most CPU on this system."

Expected: Ranked active jobs with CPU_TIME, THREAD_COUNT, TEMPORARY_STORAGE, job name/user/type/status.

💡

CPU_TIME is cumulative since job start. Check ELAPSED_CPU_PERCENTAGE for real-time activity.

2.2 — Drill Down on a Suspicious Job

Pick the top CPU-consuming non-system job, then ask:

Bob Prompt

AreaWhat to look for
RuntimeLanguage/framework, JVM version, server type

RecommendationsConcrete fixes ranked by priority

2.3 — Check Performance Collection Status

Bob Prompt
"Is there a performance data collection running on this system?"

Expected: Active collection name, profile (*STANDARDP, *EXTD2), start time, interval, and categories collected.
